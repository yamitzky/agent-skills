# deep-explain

## Overview

ユーザーが `/deep-explain` を呼んだら、対象を **3つの原則** に従って説明し直す。Claude は放っておくと「前のターンからの差分」や、英単語・専門用語を散りばめただけの要約（ルー語・ジャーゴン・造語）に逃げがちで、それが当人にしか分からない説明になる。このスキルは、その逃げを禁止して、誰が読んでも分かる説明を強制する。

ユーザーが明示的に `/deep-explain` を呼んだときだけ動く。自動発火はしない。

## 何を説明するか

- **引数あり**（例: `/deep-explain この関数` / `/deep-explain このエラー`）→ 指定された対象を説明する
- **引数なし** → **直前の自分（assistant）の発言** を説明し直す

## 3つの原則（絶対）

### 1. その応答だけで完結する

読者は会話の履歴を持っていない前提で書く。「先ほどの」「さっきの修正」「前述の通り」のような、前のターンを参照する語を使ってはいけない。説明に必要な事実は、たとえ直前に書いたことでも、その応答の中にもう一度書く。

会話の外にある内部事情（過去のやり取り、メモリ、内部ルールなど）を理由として持ち出さない。読者はそれを知らない。

### 2. 前提知識ゼロの人に向けて、背景と理由から書く

結論や「やったこと」だけを並べない。**なぜそうなるのか / なぜそれが問題なのか** を、背景から順に説明する。登場する固有名詞（システム名・部品名・サービス名）は、それが「何であるか」を一言添えてから使う。

「分かっている人なら通じる」書き方は失敗とみなす。

### 3. 言葉で説明する（ルー語・ジャーゴン・造語の禁止）

- 日本語の文章に英単語・カタカナ専門用語をそのまま混ぜない（ルー語の禁止）。
- どうしても専門用語が必要なら、**初出時に必ず平易な日本語で言い換えて** から使う。言い換えずに使ってよい用語は一つもない。
- 業界の隠語、社内造語、その場限りの coined word は、平易な言葉に開いて説明する。

例: 「root cause」→「根本的な原因」、「event loop をブロックする」→「一本の処理の流れを途中で長時間占有し、他の処理を止めてしまう」、「stg に apply 済み」→「検証用の環境（stg と呼んでいる、本番の手前のお試し環境）には反映済み」。

## 出力前の自己チェック

出力する直前に、自分の文章を読み返して次を確認する。一つでも当てはまったら直してから出す。

- [ ] 「先ほど」「さっき」「前述」など、前のターンに依存する語が残っていないか
- [ ] 説明していない英単語・カタカナ専門用語・造語が一つでも残っていないか
- [ ] 固有名詞を、それが何かを言わずに使っていないか
- [ ] 「なぜ」が抜けて、結論・手順の羅列になっていないか
- [ ] 会話の外の内部事情（メモリ・過去ログ・内部ルール）を前提にしていないか

逆に、**水増しもしない**。丁寧にするためだけの前置き、当たり前の一般論、「お役立ち」的な蛇足は入れない。分かるために必要な分だけ書く。長くするのが目的ではなく、通じるのが目的。

## よくある失敗と直し方

| 失敗 | 直し方 |
|------|--------|
| 「先ほどの修正は…」と書き出す | その応答だけで完結させる。何を修正したのかをこの応答内で一から述べる |
| 「root cause は event loop のブロック」 | 「根本的な原因は、一本の処理の流れが長時間占有され、他の処理が止まったこと」と日本語で書く |
| `stg`/`prd` をそのまま使う | 「検証用の環境（stg）」「本番環境（prd）」と、何かを添えてから使う |
| システム名をいきなり主語にする | 「app-uploader（アプリを配信用に変換して送り出す仕組み）は…」と正体を添える |
| やったことだけ並べる | 「なぜそれが必要だったか」を背景から先に説明する |
| 通じやすさのために前置きを足す | 削る。必要な情報だけ残す |

## Red Flags — これを書いていたら止めて書き直す

- 「先ほど」「さっき」「前回」「前述」「上記の通り」
- 説明なしの英単語・カタカナ語（root cause / event loop / flow control / backpressure / ack / deploy / apply / diff など）
- 説明なしの環境略語（stg / prd / dev）
- 「ご存じの通り」「いわゆる」で専門用語を流す
- 結論だけで「なぜ」がない

これらが一つでもあれば、原則のどれかに違反している。直してから出す。
